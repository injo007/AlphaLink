# Drop monitoring read-route evidence

**Scope:** Source-only map of monitoring overview AL-0116 and per-Drop monitor, statistics, and visitors routes AL-0125–AL-0127, plus their clean URL declarations AL-0454 and AL-0463–AL-0465. All eight inventory IDs (four legacy routes and four clean aliases) and their `NOT_STARTED` React status come from the [route inventory](COMMAND_OS_ROUTE_INVENTORY.csv). This sheet describes GET/HEAD reads only and does not infer semantics for Drop creation, send, stop, suppression, or other operational routes.

## Routes, access, and response

The source routes are in the authenticated web group (`auth`, `active`, `auth.session`) and each old `/app/workspaces/{workspace}/...` route is assigned `workspace.legacy-redirect`. Ordinary HTML GET/HEAD redirects to the corresponding ID-free clean URL and stores the selected active workspace. AJAX/JSON requests bypass this redirect. The route-generation loop creates `clean.console.drops.*` route names for these paths; `/drops/monitoring`, `/drops/{drop}/monitor`, `/drops/{drop}/stats`, and `/drops/{drop}/visitors` are the clean paths. See [web route group](../../apps/api/routes/web.php#L51), [route declarations](../../apps/api/routes/web.php#L148), [per-Drop route declarations](../../apps/api/routes/web.php#L157), [clean alias generation](../../apps/api/routes/web.php#L487), and [legacy redirect behavior](../../apps/api/app/Http/Middleware/RedirectLegacyWorkspaceUrl.php#L10).

Every action uses `WorkspaceDropsConsoleController::workspaceFor`: workspace must be active and belong to the signed-in user; only owner, admin, and operator roles pass. A Drop row lookup is scoped to the workspace; operators additionally see only Drops whose `user_id` is theirs. Missing or foreign Drops return 404. [Role/workspace helper](../../apps/api/app/Http/Controllers/Web/WorkspaceDropsConsoleController.php#L466), [per-Drop ownership helper](../../apps/api/app/Http/Controllers/Web/WorkspaceDropsConsoleController.php#L457). No direct privacy-officer-specific test was found for these four routes.

## Rendered controls and boundaries

- The monitoring Blade view contains a type filter and table, and loads [drops-monitor.js](../../apps/api/resources/views/console/drops/monitoring.blade.php#L46). JavaScript fetches the overview, per-Drop progress, and stats via GET; row actions include a stats expansion button and visitor link. It also constructs a PMTA link to the separate PMTA admin route. [GET refresh/statistics calls and row actions](../../apps/api/public/console-assets/drops-monitor.js#L73), [actions and stats GET](../../apps/api/public/console-assets/drops-monitor.js#L252), [stats fetch](../../apps/api/public/console-assets/drops-monitor.js#L311).
- The visitors page has a collapsible map and read-only visitor table; its script fetches chart/table data via GET. The table has search, page length, refresh, and outbound IP lookup links. No write methods or state-changing fetch calls were found in the two page scripts. [Visitors view](../../apps/api/resources/views/console/drops/visitors.blade.php#L11), [table AJAX and refresh controls](../../apps/api/public/console-assets/drops-visitors.js#L141).
- The PMTA action leaves this route family and opens the separate PMTA admin surface. Its destination and possible controls need separate route review; this sheet does not treat that link as part of the read-only monitor contract.
- No distinct JSON API route was found for this family. The same web handlers switch to JSON when the request wants JSON. All eight inventory declarations (four legacy paths and four clean aliases) remain `NOT_STARTED` for React migration; no React implementation evidence was found.

## Unknowns

- Clean aliases are generated dynamically by the route loop rather than declared as separate route statements; runtime route-list verification was not run for this documentation slice.
- Tests exercise synthetic local data. They do not establish production data completeness, polling behavior under outages, or every role/error permutation.
- No direct test found for privacy-officer denial, disabled/inactive workspace behavior per route, or the precise access policy for the outbound PMTA destination.
- DMS-derived status and historical behavior are outside this source-only sheet.
