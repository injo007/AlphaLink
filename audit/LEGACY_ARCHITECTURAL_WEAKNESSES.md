**Purpose:** Explain limitations supported by source/configuration evidence. This is not a security certification, performance benchmark, or judgment about unobserved production behavior.

## Cross-cutting evidence-backed concerns

1. **Opaque send core:** Laravel delegates delivery to a .NET apphost ELF. The apphost's direct network calls were not recovered; its managed payload has a reachable TCP text helper and SMTP-shaped reply parser, so SMTP compatibility is inferred. Literal commands, MIME/header builder, recipient checkpoint and retry flow remain unknown. Deep decompilation is unavailable here.
2. **Weakly observable process boundary:** child output is discarded, PID/progress is persisted, and terminal reconciliation is unknown.
3. **Mixed state stores:** PostgreSQL-configured models, Redis-configured queue/cache, filesystem audience/config artifacts, and remote PMTA files must remain coordinated.
4. **Retry integrity:** visitor event uniqueness and PMTA counter/file replay semantics are uneven or unknown.
5. **Security of control planes:** plain HTTP PMTA command path, NewHitPath TLS verification disabled, managed SSH host-key validation not visible, shell use, and API throttling gaps merit review.
6. **Recipient assurance gaps:** migrations do not expose explicit consent state on the subscriber table; suppression freshness, FBL complaint classification, recipient matching and suppression are unknown despite PMTA inbound configuration and reply extraction.
7. **Production evidence limits:** no database rows/catalog, logs, provider state, or live queue payloads were accessed; observed source behavior must not be treated as active-state proof.

## What cannot be concluded

The evidence does not establish current throughput, delivery rate, campaign volume, actual exploitability, customer impact, full tenant boundary, regulatory compliance, deployed version parity, or whether undiscovered systems compensate for source-level gaps.
