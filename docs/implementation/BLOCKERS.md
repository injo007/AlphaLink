1. **Remaining server list behavior:** E-SRV-02 now supports Allowed Users, lock, status, return and restore, with local authorization and transition tests. E-SRV-03 now has the local history viewer, scheduled collector and configured country lookup. Console, edit, and discovered-IP behavior remain absent or N/A. Populated DMS row-state comparison is still unavailable because the read-only relay blocks production row values.
2. **Server country fallback and visual comparison:** AlphaLink matches the DMS Pro IP-API query/cache when configured, but GeoIP2 and a MaxMind city database are not included, so the fallback is not active by default. Focused and full PHP suites pass, Pint passes, and tests use fake HTTP plus loopback; no external server or geo provider is contacted. A safe populated-history visual comparison remains open. Never request a host fingerprint.
3. **Bulk installation execution:** E-INST-02 traces DMS's synchronous child-process request, forked per-server installs and per-server caught errors. AlphaLink validates/normalizes the request and tests row-level exception isolation with a fake runner (E-INST-03); its saved-preflight platform gate matches DMS's architecture and release selection (E-INST-04). E-INST-05 adds a pure synthetic-tested DNS record planner; the Cloud bulk page filters to non-owned domains, so its normal selection follows the source command's no-provider-write branch. E-INST-06 adds pure synthetic-tested VMTA/DKIM/inbound builders and covers the CentOS 9 feedback-loop difference from CentOS 7. E-INST-07 adds the exact DMS alias word pool and random selection plus the IP planner for address deduplication, ordering and formatted-row mapping; E-INST-08 maps ISP names to VMTAs. E-INST-09 adds an offline finalization operation planner for delete-old-MTAs/IPs, IP replacement, conditional owned-domain status, saved install parameters and installed-last ordering (focused tests: 3/10; full suite: 61/498). This planner has no persistence adapter, and DMS has no transaction around finalization; actual database failure/partial-write behavior remains unknown. E-INST-10 also maps the server install stage order, already-installed/used-domain guards, and zero-IP abort before host changes; four synthetic tests verify option-gated order and those error branches. Remote address discovery and an AlphaLink ISP catalogue/data source are not connected; DMS ISP-name normalization currently accepts only supplied names. Provider/PMTA adapters are also absent. The coordinator is sequential, not wired to a route, and has no production runner. OS-specific install steps, supported package/license matrix, failure/retry/rollback behavior, synchronous progress logs and browser polling remain unimplemented or unproven. This workflow changes remote hosts and may write DNS, so INSTALL remains disabled.
4. **Registration storage and errors:** The source snapshot establishes per-IP insert/restore/ignore ordering and visible validations. DMS credential-at-rest behavior, provider existence rules, exact malformed-IP and partial-failure responses are not established. AlphaLink's encrypted secret store, workspace scope and idempotency are target safeguards, not parity evidence.

AlphaLink no longer asks for a fingerprint; Test Connection authenticates directly. Preflight automatically pins the first host key and rejects a later key change without operator input. Exact DMS success/failure feedback remains unknown because no live DMS connection is allowed.
6. **Source identity:** The read-only PHP snapshot contains source paths and line ranges in existing audit reports, but remote PHP file hashes are not available in this capture. The authenticated GET-only browser relay is restored via the existing `.env` configuration; no `.env` value, cookie, credential, or production row is stored in evidence.
