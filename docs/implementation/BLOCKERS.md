E-SRV-03 now has the local history viewer, scheduled collector and configured country lookup. Console, edit, and discovered-IP behavior remain absent or N/A. 2. **Server country fallback and visual comparison:** AlphaLink matches the DMS Pro IP-API query/cache when configured, but GeoIP2 and a MaxMind city database are not included, so the fallback is not active by default. Focused and full PHP suites pass, Pint passes, and tests use fake HTTP plus loopback; no external server or geo provider is contacted. A safe populated-history visual comparison remains open. Never request a host fingerprint.
3. **Bulk installation execution:** E-INST-02 traces DMS’s synchronous child-process request, forked per-server installs and per-server caught errors. AlphaLink validates/normalizes the request and tests row-level exception isolation with a fake runner (E-INST-03); its saved-preflight platform gate matches DMS architecture and release selection (E-INST-04). E-INST-05–10 record synthetic comparisons for DNS, VMTA configuration, alias/IP formatting, ISP names, finalization order and stage sequencing/guards. E-INST-11 maps DMS’s timestamped append-only transcript, JSON-string log endpoint and two-second/20-second polling. E-INST-12 adds a private workspace-keyed file transcript, coordinator write callback and authenticated workspace-scoped GET route; a fake-runner integration test confirms exact output plus owner/nonmember/cross-workspace behavior. The GET endpoint is not fed by a production run: there is no run-start route, real runner, child process, browser polling or log UI. E-INST-15 maps read-only IP discovery and E-INST-16 now prepares a selected row from DMS-equivalent eligibility and the workspace-scoped encrypted credential after host preflight; it remains disconnected from a production runner. The actual AlphaLink owner has no username mapping and the workspace has zero eligible domains, so there is currently no selectable server/domain pair; an AlphaLink ISP catalogue/data source remains absent; provider/PMTA adapters and production host/database adapters are absent. E-INST-13 maps OS/version assets and E-INST-14 maps their presence/skip behavior. E-INST-17 adds an allowlisted integrity verifier for the exact 4.0r8 manifest and files. The bundle exists in private host storage and passes those checks, but the running app container has no private bundle mount and PMTA_BUNDLE_DIR is unset, so its catalog correctly reports the package unavailable. Artifact integrity does not establish vendor provenance/signature, AlmaLinux runtime compatibility, or license entitlement. E-INST-18 confirms dependency resolution only in a disposable AlmaLinux 9 container; the RPM has no PGP/RSA signature metadata and the install transaction was aborted before execution. AlphaLink has no production runner and does not execute DMS's CentOS 7/9 steps. Failure/retry/rollback, synchronous progress UX and install-level health verification remain incomplete or unproven. A real install changes hosts and may write DNS, so INSTALL remains disabled.
4. **Registration storage and errors:** The source snapshot establishes per-IP insert/restore/ignore ordering and visible validations. DMS credential-at-rest behavior, provider existence rules, exact malformed-IP and partial-failure responses are not established. AlphaLink's encrypted secret store, workspace scope and idempotency are target safeguards, not parity evidence.
