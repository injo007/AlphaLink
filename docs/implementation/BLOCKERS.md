# Current parity blockers

1. **Remaining server list behavior:** E-SRV-02 now supports Allowed Users, lock, status, return and restore, with local authorization and transition tests. E-SRV-03 now has the local history viewer, scheduled collector and configured country lookup. Console, edit, and discovered-IP behavior remain absent or N/A. Populated DMS row-state comparison is still unavailable because the read-only relay blocks production row values.
2. **Server country fallback and visual comparison:** AlphaLink matches the DMS Pro IP-API query/cache when configured, but GeoIP2 and a MaxMind city database are not included, so the fallback is not active by default. Focused and full PHP suites pass, Pint passes, and tests use fake HTTP plus loopback; no external server or geo provider is contacted. A safe populated-history visual comparison remains open. Never request a host fingerprint.
3. **Bulk installation execution:** E-INST-02 traces DMS's synchronous child-process request, forked per-server installs and per-server caught errors. AlphaLink now validates/normalizes the request shape and tests a fake-runner coordinator's row-level error isolation (E-INST-03). Its saved-preflight platform gate (E-INST-04) matches DMS's x86_64 and supported-release selection. That coordinator is sequential, not wired to a route, and has no registered production runner. The OS-specific install steps, supported package/license matrix, provider writes, failure/retry/rollback behavior, IP/VMTA topology, synchronous progress logs and browser polling are not implemented or locally proven. This workflow changes remote hosts and may write DNS, so INSTALL remains disabled.
4. **Registration storage and errors:** The source snapshot establishes per-IP insert/restore/ignore ordering and visible validations. DMS credential-at-rest behavior, provider existence rules, exact malformed-IP and partial-failure responses are not established. AlphaLink's encrypted secret store, workspace scope and idempotency are target safeguards, not parity evidence.
5. **SSH Test Connection:** The DMS form and inspected SSH/SFTP call paths have no user fingerprint step, and the owner confirms none appears during Test Connection or installation. AlphaLink no longer asks for a fingerprint; Test Connection authenticates directly. Preflight automatically pins the first host key and rejects a later key change without operator input. Exact DMS success/failure feedback remains unknown because no live DMS connection is allowed.
6. **Source identity:** The read-only PHP snapshot contains source paths and line ranges in existing audit reports, but remote PHP file hashes are not available in this capture. The authenticated GET-only browser relay is restored via the existing `.env` configuration; no `.env` value, cookie, credential, or production row is stored in evidence.
7. **Data-dependent visual comparison:** DMS rows remain private. Server-list comparison used a synthetic no-match search at the same 863×892 viewport; only aggregate filtered counts differed. No production row screenshot or row text is retained. A full row-state comparison needs a sanitized synthetic DMS row fixture served by the relay.
8. **Broader reconstruction coverage:** The feature inventory is still incomplete and most DMS workflows have no AlphaLink vertical slice. The 80% milestone cannot be calculated honestly until the inventory denominator and workflow weights are complete.
9. **DMS-AUD-002 ISP/list parity:** DMS Lists selects an ISP and loads a table through `/admin/lists/:id/load`; route safety is unknown and it was not called. AlphaLink has no ISP entity or equivalent Lists page. Import column mapping, invalid-row feedback and exact failure responses also remain unverified. The new uniqueness migration deliberately fails if existing workspace contacts already have assignments in multiple lists; it does not delete or reassign them.
