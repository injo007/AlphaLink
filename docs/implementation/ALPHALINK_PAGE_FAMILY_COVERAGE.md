# AlphaLink page-family coverage map

**Purpose:** Phase 0 source inventory for planning the Command OS frontend migration. This is a route-to-source map, not a claim of workflow parity or a page-by-page acceptance record.

**Evidence date:** 2026-11-05. The current [route inventory](COMMAND_OS_ROUTE_INVENTORY.csv) contains 783 declarations: 743 `WEB` and 40 `API`. Its renderer fields classify 740 web declarations as Blade/page JavaScript, two as the Blade shell with React dashboard content, and one as a legacy redirect to that dashboard. These are declaration counts, not unique screens or completed workflow counts. The API surface has mixed response contracts, including JSON, redirects, and no-content responses; its route declarations do not mean a Blade or React screen uses them.

**Historical matrix separation:** [`FEATURE_MATRIX.md`](../reference/FEATURE_MATRIX.md) and the historical `DMS-*` evidence rows track reconstructed behavior against archived/read-only DMS references. Their status values are not frontend migration statuses and do not establish current route rendering, React coverage, or parity. This map uses the `AL-*` runtime route inventory and current AlphaLink source/tests only.

## Shared shell, authentication, and evidence boundaries

- Private web routes are in the authenticated, active-account, session-protected group in [`routes/web.php`](../../apps/api/routes/web.php#L51). Workspace resolution and role checks remain in middleware/controllers. The shell source is [`layouts/admin-shell.blade.php`](../../apps/api/resources/views/layouts/admin-shell.blade.php); a separate [`layouts/console.blade.php`](../../apps/api/resources/views/layouts/console.blade.php) exists and is not represented by the single shell.
- JSON API route groups and role boundaries are declared separately in [`routes/api.php`](../../apps/api/routes/api.php#L42). There is no evidence that the React dashboard currently fetches those API endpoints; its authenticated data is embedded by the existing Laravel dashboard controller/view contract.
- The drawer/role navigation slice has focused evidence in `WorkspaceAnalyticsDashboardTest`, `AlphaLinkCampaignSendNavigationTest`, and `command-os-drawer.test.js`; it verifies only those shell affordances, not all navigation routes.
- Existing feature test filenames were selected as representative source evidence. Individual route methods, form fields, business outcomes, denial codes, redirects, state transitions, and negative paths still need an explicit inventory and executed acceptance tests before any family can be called migrated or parity-confirmed.
- No production browser route-family walk was performed for this map. Phase 0 still needs authenticated route sampling, responsive/theme/keyboard evidence, and review of route families not covered by the recorded dashboard observation.

## Ledger claim review

The migration ledger's statements that the dashboard aliases have partial React content, that the remaining route inventory is not complete frontend parity, and that authenticated browser verification is outstanding are supported by this map and inventory. Phrase the remaining count as **782 other route declarations** after the dashboard declaration (not 782 other pages or workflows); the inventory contains 743 WEB and 40 API rows, and includes one legacy redirect. Do not infer parity percentages from either this family grouping or the historical DMS feature-matrix denominator.
