# Dashboard and analytics route evidence

**Purpose:** Phase 0 route-level evidence sheet for the dashboard/analytics family. The route IDs, methods, URIs, names, and migration fields below come from the [route inventory CSV](COMMAND_OS_ROUTE_INVENTORY.csv), which remains the route inventory source of truth. This sheet records current source and test evidence; it does not assert DMS parity or complete workflow acceptance.

**Count reconciliation:** The CSV has **8 WEB declarations** assigned to its `dashboard` and `analytics` module values (1 dashboard + 7 analytics). There is **one additional related WEB declaration**, `AL-0783`, assigned to `workspace`; it renders the same main dashboard. This sheet lists all **9 dashboard-related declarations** and does not change the CSV's module assignments.

## E-DASH-43 source update — unified partner revenue period

The React dashboard payload now derives Sponsor, ISP, Mailer and Top 10 Offer revenue from the same validated inclusive `analytics_period` window. The query reads workspace-scope campaign/Drop rows in `workspace_daily_analytics`, labels ISPs within the active workspace, and uses attributed lead revenue; per-card MTD/range overrides were removed. The no-JavaScript summary tables use the same selected-window payload. Focused verification: `WorkspaceAnalyticsDashboardTest` 25 passed / 416 assertions, TypeScript check and Vite production build passed. Production browser verification remains pending until deployment.

## E-DASH-44 source update — Marketing Graph interaction repair

`command-os-graph.tsx` now renders its module controls as native HTML buttons over the decorative SVG spokes and AlphaLink hub. All nodes from the existing workspace-scoped graph payload are kept, with the established modules ordered first. Selection is represented by `aria-pressed` and a visible activity summary; contrast and narrow-panel positioning were improved. No analytics query, API, route, permission, or dependency changed. A local Vite preview with synthetic-only fixture data verified ten node controls, mouse and keyboard activation, light/dark rendering, and 560px/350px/280px panel layouts. The production page was observed before this change with no exposed graph controls and no click feedback; production verification after delivery is pending. PHPUnit could not start on this host because PHP extensions `dom` and `xmlwriter` are unavailable.

## E-DASH-45 source update — Marketing Graph visibility and navigation

The graph now keeps its module pills readable without hover and renders role-authorized modules as native links to their existing AlphaLink pages. Campaigns, Drops and Warmups link for owner/admin/operator. Sponsors, Offers, Domains, Lists and ISPs link only for owner/admin; operators retain selectable activity nodes for those modules. Servers and Tracking link to their existing routes for graph roles. A role without a permitted destination retains a selectable activity button, and `privacy_officer` retains the existing Workspace Activity view. The existing workspace-scoped graph counts and spokes are unchanged. The payload adds a role-gated `href`; the dashboard cache namespace advances to v2 so cached v1 payloads cannot hide the new destination data. `WorkspaceAnalyticsDashboardTest` passes 26 tests / 438 assertions in the PHP 8.5 test container; TypeScript, PHP syntax and the Vite production build pass. The existing large MapLibre chunk advisory remains. Production browser verification after deployment is pending.

## Verified source behavior

- The dashboard main route and workspace-slug alias are authenticated web routes under `auth`, `active`, and `auth.session`; both add `workspace.current`. `ResolveCurrentWorkspace` resolves an active workspace membership, puts its ID in session/request attributes, and returns 404 if none is available. The controller separately permits workspace roles `owner`, `admin`, `operator`, and `privacy_officer`; a membership outside that list is denied with 403. See [`routes/web.php`](../../apps/api/routes/web.php#L51), [`ResolveCurrentWorkspace`](../../apps/api/app/Http/Middleware/ResolveCurrentWorkspace.php#L14), and [`WorkspaceAnalyticsConsoleController`](../../apps/api/app/Http/Controllers/Web/WorkspaceAnalyticsConsoleController.php#L19).
- Dashboard main rendering is Laravel Blade shell plus a React Command OS dashboard mount. `WorkspaceEntryController@dashboard` delegates to `WorkspaceAnalyticsConsoleController@index`. The normal response renders [`console/analytics/index.blade.php`](../../apps/api/resources/views/console/analytics/index.blade.php); `?fragment=1` renders [`main-dashboard-content.blade.php`](../../apps/api/resources/views/console/analytics/partials/main-dashboard-content.blade.php). See [`WorkspaceEntryController`](../../apps/api/app/Http/Controllers/WorkspaceEntryController.php#L12) and [`WorkspaceAnalyticsConsoleController`](../../apps/api/app/Http/Controllers/Web/WorkspaceAnalyticsConsoleController.php#L43). Report actions render [`console/analytics/report.blade.php`](../../apps/api/resources/views/console/analytics/report.blade.php), with [`report-results.blade.php`](../../apps/api/resources/views/console/analytics/partials/report-results.blade.php) used by ISP Stats and Mailer Revenue fragments.
- The three old `/app/workspaces/{workspace}/dashboard/...` analytics routes receive `workspace.legacy-redirect`; the middleware redirects ordinary browser GET/HEAD requests to the clean path, but lets AJAX and JSON requests through. Dynamically generated clean aliases are built from the old route definitions with `auth`, `active`, and `workspace.current`, while the legacy redirect middleware is removed. See [`routes/web.php`](../../apps/api/routes/web.php#L79) and its alias construction at [`routes/web.php`](../../apps/api/routes/web.php#L486), plus [`RedirectLegacyWorkspaceUrl`](../../apps/api/app/Http/Middleware/RedirectLegacyWorkspaceUrl.php#L11).
- Report actions call `reportContext`, which resolves the active workspace and validates date inputs; operator queries are scoped to that user in report data queries. The access-role list and report-specific data restrictions are source evidence, not evidence that every role sees identical data. See [`reportContext` and authorization](../../apps/api/app/Http/Controllers/Web/WorkspaceAnalyticsConsoleController.php#L849).

## Evidence limits and open questions

- These are current AlphaLink source and test facts. The historical DMS feature matrix is intentionally not used to infer a route's current authorization, renderer, behavior, or test coverage.
- The route inventory records frontend migration status. The six analytics-module report routes are `NOT_STARTED`; `AL-0053` is recorded as a legacy redirect; the dashboard main is `PHASE_1_TESTING_PARTIAL`. The workspace-slug dashboard alias `AL-0783` is also `PHASE_1_TESTING_PARTIAL` despite its `workspace` module classification.
- Tests exercise report data, empty states, fragments, JSON output, workspace isolation, cache behavior, and selected role scoping. They do not collectively prove every legacy redirect, every route's full HTTP response matrix, all permissions, failure messages, or visual behavior.
- Count reconciliation: the CSV verification field remains at 21 tests / 266 assertions; the latest ledger checkpoint reports 24 tests / 361 assertions for the dashboard suite. This sheet uses the ledger's later result as the current reported suite evidence and preserves the CSV unchanged as route inventory source of truth. No test suite was rerun for this documentation task. Ubuntu browser verification remains pending.
- No authenticated production browser walk or DMS comparison was performed for this sheet. Exact role behavior for every report endpoint, session expiry/invalid dates, and route alias redirect semantics require focused route assertions and browser validation.
