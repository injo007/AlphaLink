## DMS-CAMPAIGN-REDIRECT — campaign and unsubscribe resolution

**Evidence:** Read-only DMS `routes/api.php`, `RedirectHandlerController::campaign`, and `IpGeo`; AlphaLink E-TRACK-07.

DMS `POST /api/v1/campaign` requires the shared key, campaign ID, email ID, ISP ID, token, valid IP, and a `red` or `unsub` type; user-agent is optional. A wrong key returns 403. An already bot, blacklisted, or proxy recipient returns `EBE`/404. A missing or restricted campaign, or a missing Offer or Sponsor, returns `NFE`/404. ## ALPHALINK-AUDIENCE-MULTILIST — approved cross-list contact semantics

**Evidence:** DMS migration-defined `emails.lists_id` in `audit/DATABASE_ARCHITECTURE.md`; AlphaLink membership and campaign snapshot migrations; the user's explicit multi-list requirement; local baseline `AudienceListImportTest` and `DmsListUploadTest` in E-DB-02.

DMS stores one `lists_id` on an email row; live DMS uniqueness and duplicate outcomes were not queried. For AlphaLink, one normalized contact per workspace may belong to multiple Lists. Importing that contact into a new List should create that List's membership, while reimporting into the same List should be idempotent. Current importer and membership API still reject a second List, and the current passing tests assert that obsolete behavior.

The user has resolved AlphaLink's event-attribution rule (E-DB-03): when one deduplicated campaign recipient is contributed by multiple selected Lists, each selected, eligible source membership receives the open, click, or unsubscribe transition.
