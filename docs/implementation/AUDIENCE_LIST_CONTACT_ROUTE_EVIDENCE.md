# Audience, audience-list, and contact route evidence

**Purpose:** Phase 0 source map for the audience/list/contact workflow. Route IDs and module assignments below come from the [route inventory CSV](COMMAND_OS_ROUTE_INVENTORY.csv), which remains the source of truth. The current filter yields **20 WEB/API declarations**: 9 API audience-lists, 7 API contacts, and 4 WEB audiences. This sheet records AlphaLink source and tests; it does not infer parity from DMS-derived matrices.

## Shared source evidence and scope distinctions

- Web pages use the authenticated auth, active-user, and session middleware group. Legacy /app/workspaces/{workspace}/ URLs receive workspace.legacy-redirect; clean workspace paths are generated by the loop in [routes/web.php](../../apps/api/routes/web.php#L487). Audience routes are defined at [routes/web.php](../../apps/api/routes/web.php#L313).
- Web list and detail actions require an active workspace belonging to the user and allow owner, admin, operator, privacy_officer. They filter operators by each list's allowed_users. Neither action filters inactive lists: the web index can display inactive rows, and detail may load an inactive list. See [WorkspaceConsoleController](../../apps/api/app/Http/Controllers/Web/WorkspaceConsoleController.php#L3326) and AUDIENCE_ROLES at [line 71](../../apps/api/app/Http/Controllers/Web/WorkspaceConsoleController.php#L71).
- Workspace API routes inherit auth:sanctum and workspace.member. Membership middleware restricts access to active workspaces with a user membership, returns 404 otherwise, and attaches workspace and role to the request. workspace.role then gates roles with 403. See [routes/api.php](../../apps/api/routes/api.php#L43), [EnsureWorkspaceMember](../../apps/api/app/Http/Middleware/EnsureWorkspaceMember.php#L12), and [EnsureWorkspaceRole](../../apps/api/app/Http/Middleware/EnsureWorkspaceRole.php#L10).
- **Mapping concern for React parity review:** API AudienceListController index/show/findList restrict lists to the active workspace and active list status but do not apply the web operator allowed_users filter. The API read group admits operators. Thus operators may see lists via API that are hidden from the web page; conversely, inactive lists visible in web index/detail are excluded by API. This is observed behavior, not classified here as a bug or product decision. Resolve intended parity before a React screen changes data source. See [API index/show/findList](../../apps/api/app/Http/Controllers/Api/V1/AudienceListController.php#L28) and [web list filters](../../apps/api/app/Http/Controllers/Web/WorkspaceConsoleController.php#L3326).
- API contacts and consent-record GET and POST routes all allow owner/admin/operator/privacy_officer, so the current policy permits privacy_officer to create contacts and write consent records. Suppression-event POST separately permits owner/admin/privacy_officer. Audience-list create/member-add/import/remove allow owner/admin/operator; import status also excludes privacy_officer. These are source facts to preserve and review, not inferred deviations. Rate limits are recorded in the route rows from [routes/api.php](../../apps/api/routes/api.php#L53).
- Contact response presenters mask email addresses; list membership responses also mask member addresses. Consent/suppression history returns recorded event fields. API existence does not prove React consumption: all 20 rows have NOT_STARTED React migration status. See [ContactController presenter](../../apps/api/app/Http/Controllers/Api/V1/ContactController.php#L137) and [AudienceListController members](../../apps/api/app/Http/Controllers/Api/V1/AudienceListController.php#L57).
- For web tests, [Tests\TestCase::get](../../apps/api/tests/TestCase.php#L16) rewrites old workspace browser URLs to clean paths before dispatch. A route-name get() therefore does not test the old route's redirect middleware. getLegacyWorkspacePage() uses parent::get() for raw browser redirect tests. API getJson() is not rewritten.

## Limits and unresolved workflow coverage

- React migration is NOT_STARTED on all 20 rows in the CSV. The Blade audience list and detail pages remain the visible web renderers. No inspected source/test establishes a React client consuming these APIs.
- AudienceListImportTest covers import, idempotency, privacy-safe error handling, role rejection, and some list creation. AlphaLinkOfferScopedSuppressionTest covers offer-scoped suppression. Most list/contact/consent/suppression read endpoints have no direct route tests.
- No DMS-derived feature status was used to fill route facts. The route inventory's behavior_verification field delegates to other records; this sheet does not treat that as proof for an individual HTTP contract.
- A complete route walk still needs direct unauthorized/member/foreign-workspace assertions, API cursor contracts, operator allowed_users parity decisions, inactive-list parity decisions, contact/consent/suppression privacy and role review, failure response checks, and saved browser evidence for both audience pages.

At the same viewport, the event entries read as a dense text stack with weak grouping between actions and timestamps. The screenshot was captured and inspected during this audit, but was not saved to the workspace. Keyboard and responsive behavior, authorization variants, and candidate parity remain untested.
